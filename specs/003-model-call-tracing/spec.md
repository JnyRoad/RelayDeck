# Feature Specification: 模型调用追踪

**Feature Branch**: `003-model-call-tracing`
**Created**: 2026-09-03
**Status**: Approved
**Input**: 为 RelayDeck 的模型网关调用保存可查询的客户端请求与模型响应，并允许管理员安全查看和按策略自动清理。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 定位模型网关调用 (Priority: P1)

管理员需要根据时间、请求标识、调用方、模型和结果，找到一次模型网关调用，并立即判断调用是否成功、耗时是否异常、请求或响应是否完整保存。

**Why this priority**: 没有轻量可筛选的调用索引，就无法高效排查模型网关问题。

**Independent Test**: 创建一条成功调用和一条失败调用后，管理员能在调用详情列表中筛选到各自的摘要，且不加载任何正文。

**Acceptance Scenarios**:

1. **Given** 已记录模型网关调用，**When** 管理员按请求 ID 或时间范围查询，**Then** 系统返回对应调用摘要及请求、响应采集状态。
2. **Given** 调用被策略拦截或上游失败，**When** 管理员查看列表，**Then** 系统明确显示失败阶段和终态，而不将其显示为成功。

---

### User Story 2 - 安全查看请求与模型回复 (Priority: P1)

管理员需要在不拖慢列表的前提下，查看一次模型网关调用的客户端请求和实际返回给客户端的模型回复，以复现和定位问题。

**Why this priority**: 排障所需的核心证据是请求与最终响应的关联内容，而不只是成本和 Token。

**Independent Test**: 管理员打开一条调用详情时，先看到摘要；仅在打开正文页签后才获得该正文，且正文的截断或脱敏状态可见。

**Acceptance Scenarios**:

1. **Given** 一条带文本请求和模型回复的调用，**When** 管理员打开详情，**Then** 可以分别查看结构化内容和原始协议内容。
2. **Given** 正文超过保存上限、含敏感凭据或属于不保存的二进制内容，**When** 管理员查看详情，**Then** 系统显示准确的截断、脱敏或不适用状态，不伪装为完整内容。

---

### User Story 3 - 管理留存与清理 (Priority: P2)

管理员需要控制是否记录调用正文、设置自动清理的保留天数，并安全地执行手动清理。

**Why this priority**: 原始模型内容增长快且敏感，缺少留存控制会带来容量和隐私风险。

**Independent Test**: 设置自动清理策略后，过期调用及其全部正文被删除，未过期调用和现有用量记录不受影响。

**Acceptance Scenarios**:

1. **Given** 管理员开启自动清理并设置保留天数，**When** 清理任务运行，**Then** 仅删除到期的调用追踪记录及其正文。
2. **Given** 管理员发起手动清理，**When** 尚未确认，**Then** 系统先返回匹配数量和数据量预览；确认后才开始删除。

### Edge Cases

- 流式响应在完成前被客户端断开时，调用必须记录为中断或部分完成，并保留已安全采集的内容状态。
- 请求被网关策略拦截、参数校验拒绝或上游不可用时，仍必须留下可查询的调用摘要。
- 请求或响应正文超过上限时，必须保留原始大小和哈希，并显式标记截断。
- 音频、图片、视频和 Base64 等二进制或大媒体内容不得作为可读正文保存。
- 追踪存储暂时不可用时，模型网关调用不得因追踪功能失败而被阻断。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须为每次模型网关逻辑调用生成唯一的追踪标识，并关联已有请求标识、调用方、模型、路由、协议和时间信息。
- **FR-002**: 系统必须记录成功、失败、拦截、中断和部分完成等终态，并记录可用于排障的状态码、错误阶段、耗时和首字节时间（可用时）。
- **FR-003**: 系统必须保存客户端请求和最终返回给客户端的模型响应；当网关改写或重试上游请求时，系统应保留可关联的上游尝试摘要。
- **FR-004**: 系统必须为同步、流式和 WebSocket 模型网关调用提供一致的调用追踪语义；WebSocket 的每个模型调用轮次必须可独立查询。
- **FR-005**: 系统必须在正文保存前不可逆地移除认证凭据和识别出的敏感字段，且不得保存原始二进制媒体或 Base64 大字段。
- **FR-006**: 系统必须为每种正文明确标记完整、截断、脱敏、不适用或采集失败状态，并保留原始与已保存大小及内容哈希。
- **FR-007**: 管理员必须能按时间、请求标识、调用方、模型、路由、协议、结果和采集状态筛选调用摘要。
- **FR-008**: 调用摘要列表不得返回正文；正文必须按单次调用、单种正文按需读取。
- **FR-009**: 系统必须将调用详情作为现有用量记录界面的独立页签，并允许从相关用量记录跳转到调用详情。
- **FR-010**: 系统必须提供调用追踪总开关、正文采集开关、自动清理开关和保留天数设置。
- **FR-011**: 自动清理必须仅删除到期调用追踪及其正文，必须支持分批执行、重复执行保护和运行结果记录。
- **FR-012**: 手动清理必须先返回预览，再经明确确认后执行；任何清理不得删除现有用量记录或提示词审计记录。
- **FR-013**: 只有已认证管理员可以查询调用摘要和正文；正文读取、复制和清理必须产生不含正文的操作审计记录。
- **FR-014**: 追踪功能默认关闭；开启后若采集失败，必须暴露可观测错误状态并保持模型网关原有可用性。

### Key Entities

- **调用追踪**: 一次可独立排障的模型网关逻辑调用，承载身份、路由、模型、时序、结果和到期信息。
- **调用正文**: 归属于一次调用的请求、模型回复、上游尝试或错误内容，带有采集和安全状态。
- **留存策略**: 管理员设置的追踪、正文和自动清理开关，以及合法的保留期。
- **清理运行记录**: 一次自动或手动清理的范围、结果、失败信息和操作者信息，不含被删除正文。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员能在选择的时间范围内通过请求 ID 在一次查询中定位对应调用摘要。
- **SC-002**: 详情列表在每页最多 100 条记录时不传输任何请求或响应正文。
- **SC-003**: 对测试覆盖的同步、流式、WebSocket、失败和拦截调用，100% 生成可查询终态或明确的采集失败状态。
- **SC-004**: 针对认证凭据和 Base64 媒体的安全回归样本，持久化数据、管理接口和应用日志均不出现原始敏感值。
- **SC-005**: 自动清理后，所有到期调用及其正文不可再查询，未到期调用和用量记录保持可查询。

## Assumptions

- 本期仅覆盖模型网关调用，不覆盖普通管理或业务 REST 接口。
- 现有管理员认证是调用详情的准入边界；细粒度角色与二次验证不在本期新增范围，但正文读取和清理将保留操作审计。
- 正文默认不采集；管理员显式开启后，单个正文初始上限为 1 MiB，超过上限按截断处理。
- 自动清理默认关闭；管理员开启后可设置 1 至 90 天，初始建议值为 7 天。
- 本期优先保存客户端请求和客户端可见响应；上游多次尝试先保存摘要和关联关系，不承诺完整上游原始线报。
- 追踪内容的生产容量、法务留存要求和实际管理员权限模型尚未在真实环境验证；上线前必须完成容量与合规核验。
