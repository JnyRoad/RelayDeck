# Quickstart: 模型调用追踪验证

## 前置条件

- 后端配置有固定的 `TOTP_ENCRYPTION_KEY`，且数据库已执行本功能迁移。
- 使用测试或隔离环境；不以真实生产对话作为正文采集样本。
- 管理员可登录管理面，且测试 API Key 可调用至少一个同步模型和一个流式模型。

## 场景 1：默认关闭

1. 保持调用追踪和正文采集关闭。
2. 发起一次模型网关请求。
3. 在调用详情页确认没有新追踪正文，且原网关响应与用量记录行为不变。

## 场景 2：同步与流式调用

1. 开启追踪和正文采集，关闭自动清理。
2. 发起一条小型同步请求和一条小型 SSE 请求。
3. 用请求 ID 在调用详情中找到两条记录。
4. 确认请求与响应在不同正文页签按需加载；SSE 的最终客户端事件流与客户端实际收到的内容一致。

## 场景 3：安全边界

1. 在请求头和 JSON 中放入测试专用凭据 canary，并提交包含 Base64 大字段的请求。
2. 查看调用详情、数据库测试查询和应用日志。
3. 确认 canary 与 Base64 内容均未保存，详情显示脱敏或不适用状态。

## 场景 4：失败与中断

1. 对不存在模型发起请求，或让测试上游返回失败。
2. 中断一条正在流式返回的测试请求。
3. 确认对应调用分别显示失败与中断/部分完成，且不显示为成功。

## 场景 5：留存

1. 设置自动清理和较短的测试保留期，或使用手动清理预览。
2. 检查预览数量与确认后结果一致。
3. 确认到期调用及正文不可查询，未到期调用、既有用量记录和提示词审计仍存在。
