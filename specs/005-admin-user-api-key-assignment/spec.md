# Feature Specification: 管理员用户 API 密钥完整管理

**Feature Branch**: `005-admin-user-api-key-assignment`
**Created**: 2026-09-04
**Status**: Ready for review
**Input**: 管理员从用户管理打开“用户 API 密钥”后，需要得到与 `/keys` 用户 API 密钥页面功能等同的目标用户版密钥控制台。唯一的上下文差异是操作对象固定为当前选中的用户，不是管理员自己。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在用户管理中完整管理目标用户的 Key (Priority: P1)

管理员从某位用户的操作菜单打开 API 密钥模态框后，可以像该用户本人访问 `/keys` 一样搜索、筛选、分页、查看用量与状态、创建、编辑、启停、调整分组、重置额度/限流用量和删除该用户的 Key。

**Why this priority**: 关闭自助注册或登录时，管理员必须能独立完成用户开通、凭据配置、日常维护和撤销；只读列表或局部按钮不能完成管理闭环。

**Independent Test**: 管理员选择一名有多把 Key 的用户，能在模态框中按状态和分组筛选、编辑一把 Key 的配置、启停或删除它，并确认所有变更只作用于该目标用户。

**Acceptance Scenarios**:

1. **Given** 目标用户有多把 Key，**When** 管理员打开模态框，**Then** 可使用与 `/keys` 一致的刷新、搜索、分组/状态筛选、排序、分页和列设置查看该用户自己的 Key 摘要、用量、并发、到期、状态和最近使用信息。
2. **Given** 目标用户没有 Key，**When** 管理员点击创建，**Then** 可使用与 `/keys` 一致的创建表单为该用户生成随机 Key，或在开启自定义 Key 时提交经过相同规则校验的自定义 Key。
3. **Given** 管理员编辑目标用户的一把 Key，**When** 提交有效修改，**Then** 可修改名称、分组、状态、IP 规则、额度、到期和限流配置，并可按原页面能力重置额度或限流用量。
4. **Given** 管理员启用、停用、修改分组或删除一把 Key，**When** 操作完成，**Then** 目标用户的列表和运行时访问状态即时反映变化；删除必须二次确认。
5. **Given** 目标用户的 Key 可用于客户端配置，**When** 管理员点击“使用密钥”或 CCS 导入，**Then** 获得与 `/keys` 相同的使用指引和 CCS 导入体验，并遵守系统对 CCS 导入入口的现有开关。

---

### User Story 2 - 掩码显示并复制目标用户的完整 Key (Priority: P1)

管理员需要在目标用户版控制台中看到和 `/keys` 一致的掩码 Key，并通过复制按钮取得完整值，把凭据交付给该用户或用于排障。

**Why this priority**: 当前图 3 中的模态框仅截断展示 Key，既不能复制，也无法承担管理员代管用户凭据的职责。

**Independent Test**: 管理员打开一名有既存 Key 的目标用户，点击复制后剪贴板内容与这把 Key 的实际完整值一致，同时列表仍只显示掩码值。

**Acceptance Scenarios**:

1. **Given** 目标用户已有一个或多个 Key，**When** 管理员查看列表，**Then** Key 按 `/keys` 规则掩码显示，且每行都有复制完整值的入口和成功/失败反馈。
2. **Given** 管理员刚为目标用户创建 Key，**When** 创建成功，**Then** 新 Key 立即出现在同一列表中，可直接复制完整值，无需切换到目标用户登录态。
3. **Given** 浏览器拒绝剪贴板权限，**When** 管理员执行复制，**Then** 不向剪贴板写入内容，显示失败原因并允许重试，不改变 Key 状态。

---

### User Story 3 - 安全地隔离与追溯管理员代管操作 (Priority: P2)

管理员需要能够追溯针对目标用户的 Key 管理操作，同时完整 Key 不应出现在普通摘要、通知、错误或审计正文中。

**Why this priority**: 管理员需要跨用户管理凭据，但任何越权或跨用户误操作都会造成严重访问错误。

**Independent Test**: 管理员对用户 A 的 Key 执行创建、读取、更新、启停、重置或删除后，审计能定位操作者、目标用户、Key 标识、动作和时间；所有条目均无完整 Key，用户 B 的 Key 不发生变化。

**Acceptance Scenarios**:

1. **Given** 管理员在目标用户的控制台执行任意 Key 管理动作，**When** 系统记录审计，**Then** 审计包含操作者、目标用户、Key 标识、动作和时间，且不含完整 Key。
2. **Given** 管理员切换用户或提交滞后的请求，**When** 系统加载或修改 Key，**Then** 读取和变更必须同时验证 Key 属于请求中的目标用户，绝不能显示或修改其他用户的 Key。
3. **Given** 用户列表、调用追踪列表或其他常规摘要被加载，**When** 管理员未打开该用户的密钥控制台，**Then** 系统不得返回完整 Key。

### Edge Cases

- 目标用户不存在或已删除：不读取、不创建或修改 Key，明确显示原因；目标用户被停用时，允许只读查看其掩码 Key、分组和用量，但拒绝创建、编辑、启停、重置和删除。
- 随机或自定义 Key 生成、校验、写入失败：不显示不存在的 Key，不留下半成品记录。
- 同一创建提交因网络重试到达多次：只创建一把 Key，后续响应指向同一创建结果。
- 目标用户的分组、订阅、IP、额度、限流或到期配置不合法：使用与 `/keys` 相同的校验并拒绝该次变更。
- 已失效、额度耗尽或已停用的 Key：继续显示状态和掩码值；复制不会重新启用它。
- 删除确认被取消：不改变任何 Key；确认删除后，只有目标 Key 失效且列表刷新。
- 管理员在请求未完成时关闭模态框或切换目标用户：迟到响应不得覆盖新目标用户的列表或向其显示旧用户 Key。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 管理员从用户管理打开某位用户的 API 密钥模态框时，必须获得与 `/keys` 页面当前发布版本等同的 Key 管理功能；仅全局页面导航和“当前用户”上下文替换为目标用户上下文。
- **FR-002**: 目标用户版控制台必须支持刷新、搜索、按分组和状态筛选、服务端排序、分页和列可见性设置，并展示与 `/keys` 同等的 Key 摘要、分组、并发、用量、额度、限流、到期、状态、创建和最近使用信息。
- **FR-003**: 管理员必须能为目标用户创建随机 Key 或受现有验证约束的自定义 Key，并配置与 `/keys` 创建表单相同的名称、分组、IP 白名单/黑名单、额度、限流和到期选项。
- **FR-004**: 管理员必须能为目标用户编辑 `/keys` 可编辑的 Key 配置，包括名称、分组、状态、IP 规则、额度、限流和到期；额度与限流用量重置必须使用同样的确认和效果。
- **FR-005**: 管理员必须能在活动目标用户的控制台启用、停用和删除其 Key；删除必须二次确认，成功后 Key 对模型网关立即失效。目标用户被停用时，创建、编辑、启停、重置和删除均必须被拒绝，但只读查看可用。
- **FR-006**: 管理员模态框必须以与 `/keys` 一致的掩码格式显示 Key，并通过复制入口将实际完整值写入剪贴板；界面、通知和错误正文不直接展示完整值。
- **FR-007**: 管理员必须能对目标用户的 Key 使用与 `/keys` 相同的“使用密钥”配置指引和 CCS 导入功能；现有产品配置若隐藏 CCS 导入入口，管理员模态框也必须隐藏它。
- **FR-008**: 每一个读取或变更请求必须携带并验证明确的目标用户归属；Key 不属于该用户时，系统不得读取、复制、更新、启停、重置或删除它。
- **FR-009**: 新建、更新、启停、重置和删除 Key 必须使用与 `/keys` 一致的业务校验、权限边界、缓存失效与运行时生效语义；不能因管理员入口而绕过目标用户的分组或订阅约束。
- **FR-010**: Key 创建必须是幂等的：同一管理员对同一目标用户的同一逻辑提交因网络重试不会产生多把 Key。
- **FR-011**: 只有已认证管理员可以使用目标用户版控制台；所有目标用户 Key 的服务端 HTTP 管理请求（列表、创建、更新、启停、重置、删除、分组/倍率和目标范围用量）必须记录管理员审计，包含操作者、目标用户、Key 标识（适用时）、动作和时间，但不得包含完整 Key。浏览器本地的复制、使用指引和 CCS 导入不单独发送审计事件，且不得为了审计而上传完整 Key。
- **FR-012**: 用户列表、调用追踪列表和其他不需要 Key 正文的常规摘要不得包含完整 Key。
- **FR-013**: 创建、读取、复制、更新、启停、重置、删除或 CCS 导入的失败不得意外改变其他 Key、其他用户或已使用额度，并向管理员展示可操作的错误原因；本地复制、使用指引和 CCS 导入失败不得生成或上传包含完整 Key 的审计正文。

### Key Entities

- **目标用户密钥控制台**: 嵌入用户管理模态框、代表一位明确用户执行 `/keys` 全部功能的工作区。
- **目标 Key**: 归属于当前目标用户的一把 API Key，包含完整值、界面掩码、状态、配置、用量和归属验证。
- **管理员代管操作**: 管理员代表目标用户执行的服务端读取、创建、更新、启停、重置或删除，以及浏览器本地的复制、使用指引和 CCS 导入动作。
- **敏感凭据管理事件**: 由服务端目标用户 Key HTTP 管理请求产生的不包含完整 Key 的管理员审计记录，关联操作者、目标用户、目标 Key（适用时）、动作和时间。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员无需成为目标用户、无需目标用户登录，即可在该用户的密钥控制台完成 `/keys` 的全部已发布功能。
- **SC-002**: 对每一项 `/keys` 已发布 Key 管理操作，目标用户版控制台产生与用户本人页面相同的业务结果、验证结果和运行时效果。
- **SC-003**: 对已有或新建的目标 Key，管理员能从掩码列表复制完整值，复制结果与存储值完全一致。
- **SC-004**: 确认删除某个目标用户的 Key 后，该 Key 不再显示且不能用于模型调用；取消确认不改变任何 Key。
- **SC-005**: 所有跨用户 Key 读取或变更请求均验证 Key 属于目标用户；测试覆盖中不得出现跨用户读取或修改成功。
- **SC-006**: 管理员 Key 管理审计可定位操作者、目标用户、Key 标识和时间，审计、常规摘要和错误正文均不含完整 Key。

## Assumptions

- “完全要有 `/keys` 页面功能”指同一发布版本的所有 Key 管理行为、验证、可见信息和操作入口都必须等价；用户管理页面的外层导航、账户资料和目标用户标识不需要复制成独立页面。
- 目标用户版控制台以当前选中的用户为唯一数据归属；管理员自身的 Key 与目标用户的 Key 永不混合。
- 现有 `/keys` 页面已经使用掩码显示并在点击复制时使用完整值；管理员模态框遵循同一凭据呈现方式。
- 如果未来 `/keys` 新增可用 Key 管理功能，目标用户版控制台必须同步纳入同等能力或明确标记为暂不可用，不能静默产生功能缺口。
